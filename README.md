# Задание 2. Thread pool

**Дедлайн:** 06.12.2026 23:59

Реализуйте пул потоков с фиксированным числом потоков и собственные future с поддержкой цепочек вычислений.
Интерфейсы `ThreadPool` и `LightFuture` и исключение `LightExecutionException` уже есть в проекте, менять их нельзя.

## ThreadPool

- Каждый поток либо ждёт задачу, либо выполняет её. Ожидание не должно быть активным: поток без работы не тратит процессор.
- Задача — вычисление значения, вызов `get` у `Supplier`. Метод `submit` принимает задачу и сразу возвращает `LightFuture`, не дожидаясь её выполнения.
- Если в пуле есть свободный поток, он берёт задачу. Иначе задача ждёт в очереди, пока какой-нибудь поток не освободится.
- `getNumberOfThreads` возвращает число потоков пула.
- `shutdown` прерывает потоки пула через `Thread.interrupt()` и дожидается их завершения. Задачи из очереди, которые не успели начаться, не выполняются: их `get` завершается с `LightExecutionException`.

## LightFuture

- `isReady` возвращает `true`, если задача завершилась — с результатом или с исключением.
- `get` возвращает результат задачи. Если результат ещё не готов, поток ждёт его.
  - Если `supplier` бросил исключение, `get` бросает `LightExecutionException`, причиной (`getCause`) которого является это исключение.
  - Если ждущий поток прервали, `get` бросает `InterruptedException`.
- `thenApply` принимает `Function`, которая применяется к результату этой задачи `X`, и возвращает новую задачу `Y`.
  - `Y` выполняется не раньше, чем завершится `X`, и выполняется в том же пуле на общих основаниях.
  - Пока `X` не завершилась, `Y` не занимает поток пула.
  - Если `X` завершилась с исключением или исключение бросила `Function`, `get` у `Y` бросает `LightExecutionException`.
  - `thenApply` можно вызвать у одной задачи несколько раз.

Все методы обоих интерфейсов должны быть потокобезопасны.

## Ограничения

Из `java.util.concurrent` можно использовать только `ReentrantLock` и `Condition` из `java.util.concurrent.locks` и классы `Atomic*` из `java.util.concurrent.atomic`.
Очереди, executor-ы, `CompletableFuture` и прочее из этого пакета в решении использовать нельзя. В тестах — можно.
`synchronized`, `wait` и `notify` использовать можно.

## Запуск

```
mvn clean verify
```

`mvn verify` запускает тесты и все проверки (checkstyle, Error Prone, NullAway, SpotBugs).
