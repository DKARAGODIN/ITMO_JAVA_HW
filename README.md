На выбор предложено несколько проблем для исследования. Выберите одну, которая вам больше всего нравится, напишите бенчмарк, проведите замеры и опишите полученные результаты.
Если вы делаете несколько тестов с разными параметрами, используйте аннотацию `@Param` и добавьте графики.

## Варианты

1. Читать массив байт из файла в Java можно несколькими способами: https://www.baeldung.com/java-convert-file-byte-array.
   Какой из способов самый быстрый? Как это меняется в зависимости от размера файла?

2. В стандартной библиотеке есть несколько потокобезопасных реализаций интерфейса `Map`, и в однопоточном режиме за потокобезопасность приходится платить.
   Измерьте, насколько `ConcurrentHashMap` и `ConcurrentSkipListMap` медленнее, чем `HashMap`, в однопоточном режиме.
   Проверьте разные сценарии: размер карты, соотношение `get` и `put`, поиск существующего и отсутствующего ключа.

3. Кроме обычных сильных ссылок (`Object o = new Object();`) в Java есть `SoftReference`, `WeakReference` и `PhantomReference`.
   Они несут оверхед, поскольку GC обязан обрабатывать их по-особому.
   Определите, насколько медленнее создание таких ссылок по сравнению с обычными.
   Реальные приложения не только создают ссылки, но и выполняют полезную работу: эмулируйте её с помощью `Blackhole.consumeCPU`.

4. Вам нужен самый быстрый счётчик для многопоточного режима. Самая простая реализация — инкремент в блоке `synchronized`. Второй способ — интерфейс `Lock`, третий — `AtomicLong`, четвёртый — `LongAdder`.
   Сравните, какой способ быстрее в зависимости от нагрузки: числа потоков и соотношения записей и чтений.

5. Ваш веб-сервер постоянно отправляет очень простые JSON из двух полей — id сообщения и `ACK` или `NAK`, например `{"id":1,"response":"NAK"}`.
   Определите, какая библиотека сериализации быстрее: Gson или Jackson. А может, быстрее склеить строку руками?
   Библиотеки добавьте в `pom.xml` сами.

6. Сколько стоит исключение? Сравните возврат кода ошибки, выброс исключения с полным стектрейсом и выброс исключения без стектрейса (конструктор `Throwable(String, Throwable, boolean, boolean)`).
   Как результат зависит от глубины стека в момент выброса? Глубину задайте через `@Param`.
   Отдельно проверьте, что будет, если исключение создать один раз и выбрасывать повторно.

7. Один и тот же вызов `shape.area()` на массиве фигур работает с разной скоростью в зависимости от того, сколько разных классов фигур в массиве.
   Сравните массивы из 1, 2, 3 и 4 типов фигур. Сравните виртуальный вызов с `switch` по `sealed`-интерфейсу.

8. Может, у вас есть своя хорошая идея, что померить? Делайте свой вариант.

## Запуск

В проекте уже готов `HelloWorld`. Чтобы его запустить, соберите проект Maven-ом и запустите jar-файл:

```
mvn clean verify
java -jar target/benchmark.jar
```

`mvn verify` запускает и все проверки (checkstyle, Error Prone, SpotBugs). `mvn package` собирает jar без SpotBugs.

## Что сдать

В своей ветке, кроме кода:

- `RESULTS.md` — описание результатов;
- графики с результатами. Сырые результаты JMH в JSON: `java -jar target/benchmark.jar -rf json -rff results.json`. Графики по нему можно построить на https://jmh.morethan.io.

Подумайте, что нужно обязательно указывать при описании результатов производительности.
Также в описании результатов обязательно должно быть объяснение, **почему** результат именно такой, а не только какой вариант быстрее. Помогут профайлеры JMH, например `-prof gc` для аллокаций.
